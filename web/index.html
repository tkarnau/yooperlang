A systems language with a TypeScript feel.

No garbage collector. No classes. Structs and free functions. Behavior expressed through two orthogonal mechanisms: traits and kinds.

A taste of Yooperlang

Types on the right. Templates with ${...}. main returns an int32 exit status. 

type Point {
    x: int32,
    y: int32,
}

type Rect {
    pos: Point,
    length: int32,
    width: int32,
}

function is_intersecting(a: Rect, b: Rect): bool {
    return a.pos.x < b.pos.x + b.width
        && b.pos.x < a.pos.x + a.width
        && a.pos.y < b.pos.y + b.length
        && b.pos.y < a.pos.y + a.length;
}

function main(): int32 {
    let r1: Rect = { pos: { x: 5, y: 9 }, length: 10, width: 10 };
    let r2: Rect = { pos: { x: 2, y: 2 }, length: 10, width: 10 };

    const hit: bool = is_intersecting(r1, r2);
    printf(`is intersecting: ${hit}\n`);
    return 0;
}

Three layers, kept separate

Type

What the value is — the concrete shape of data. int32, Point, FileHandle.

Trait

What the value can do — operations it supports. Disposable, Iterable<T>, Task<T>.

Kind

How the binding must be used — lifecycle and scoping rules. disposable, scoped, pooled.
