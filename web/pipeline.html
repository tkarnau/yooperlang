The pipeline

Watch a program become a binary

Source goes in, five stages happen, an executable comes out. Everything on this page is a real dump from a real build: the token stream is what --dump-tokens printed, the tree is what --dump-ast-json wrote, the LLVM is what --keep-ir left behind, and the output is what the binary printed when it ran.

Program

    What each stage is

    Five stages, one direction

    1. lex

    Text becomes tokens

    A flat stream of tagged spans. Every token records its byte offset and length, which is what lets a diagnostic later point a caret at the exact column.

    2. parse

    Tokens become a tree

    A hand-written recursive descent parser. Note the tokens that vanish here: braces, semicolons and commas are structure, so they end up as the shape of the tree rather than as nodes in it.

    3. typecheck

    The tree gets an opinion

    Types are resolved, generics monomorphized, trait impls matched to bounds, kind clauses enforced, and every path checked for a return. This stage produces the diagnostics you see everywhere else on this site, so a clean build shows nothing.

    4. codegen

    The tree becomes LLVM IR

    Text, not bitcode. A struct becomes an LLVM aggregate, ref becomes a pointer, a kind's mustCall becomes an actual call placed on every exit path.

    5. link

    clang does the rest

    The compiler shells out to clang with the emitted .ll, the small C runtime, and any -l flags your extern blocks asked for. What lands next to your source is an ordinary native executable.

    bonus

    It is all inspectable

    --dump-tokens, --dump-ast (which writes a cross-linked HTML viewer much like this page), --dump-ast-json, --keep-ir, and --track-heap. None of it is a debug build.

    Dumps regenerated by npm run gen:web from the programs in the repository.
