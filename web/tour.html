Get the compiler

Grab the release, unpack it, and check that you have clang. The compiler emits LLVM IR and shells out to clang to link, so clang is not optional and is not in the box. 

curl -LO https://github.com/tkarnau/yooperlang/releases/download/v0.1.0/yoopiler-boot-0.1.0-linux-x64.tar.gz
tar xzf yoopiler-boot-0.1.0-linux-x64.tar.gz
cd yoopiler-boot-0.1.0-linux-x64

clang --version                # you need this
./bin/yoopiler_boot            # prints its usage

Linux x64 only. If you have a checkout instead, build the compiler from bootstrap/src/main.yoop and it does the same job.

what you just downloaded

The compiler for Yooperlang, written in Yooperlang, compiled by itself. The binary was built by a compiler built by a compiler built from the same source, and the last two came out byte-identical. It handles the subset the compiler itself is written in, which is most of the language but not all of it.

1. Hello

Put this in hello.yoop, build it, run it. The binary lands wherever -o says and needs nothing installed to run. 

./bin/yoopiler_boot hello.yoop -o hello
./hello
echo $?

Every program starts at main, and the int32 it returns is the process exit code. Nothing wraps it, which is why echo $? prints 0. printf is the one function always in scope.

2. Functions

Parameters and return types are always annotated. Inside a body, types are inferred when the initializer makes them obvious.

Two things to notice. There are no implicit numeric conversions in either direction, so a widening is written out as float32(n). And ref appears at the declaration and at the call site, so a function that mutates its argument cannot do it quietly.

3. Strings and logging

There are two string types and the split is ownership. A string is a borrowed view: literals are strings, nothing frees them, and they are what you pass to anything that only reads. A Text owns a growable buffer and is what you build with.

That matters more than it looks. Every template literal and every concatenation is a fresh allocation that nothing frees, so anything accumulating text in a loop should be a Text. Logging is three functions in std/log.yoop and goes to stderr, which is why it lands in a separate pane below.

two import rules

Values from std/ must be namespaced (import * as text from "std/core/text.yoop";), because a bare info or push would shadow your own names everywhere. Types, traits and kinds are exempt and come in by name.

4. Traits

A trait is a capability: the operations a type promises to provide. It is the only polymorphism in the language. No classes, no inheritance. A type on its own is just a struct - fields and nothing else - and implements is how it takes on behavior.

Calls are trait-qualified, Greeter.greet(ref g) rather than g.greet(). That looks verbose for about five minutes, and then you notice that two traits on one type can both have a greet with no ambiguity and no resolution order to learn. Generics monomorphize against the bound, so announce becomes one machine function per type you actually call it with.

5. Kinds

This is the part that is not like the other languages. A type says what a value is, a trait says what it can do, and a kind says how the binding must be used. A kind attaches to the binding, not the type, so the same type in two bindings can carry different obligations.

Compare plain and kinded in the output below: same type, same literal, one word of difference, and one of them cleans up. Then look at bail, where close 3 still prints on the early return. You declare the obligation once instead of remembering it on every branch.

disposable is not a compiler builtin. It is four clauses in std/core/kinds.yoop, and a kind you declare yourself gets the same treatment.

The flip side, stated plainly: plain leaks and the compiler says nothing. Ownership is advisory until you ask for it with the keyword. An earlier version made unhandled resources a hard error and it was miserable to use.
