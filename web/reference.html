Overview

Yooperlang separates three ideas that other languages tend to conflate: types (what a value is), traits (what it can do), and kinds (how a binding must be used).

A type describes data - int32, Point, FileHandle. A trait is a set of operations a type provides - Disposable, Iterable<T>. A kind is a usage contract attached to a binding - disposable, scoped, pooled. 

type FileHandle implements Disposable {
    fd: int32,
    function dispose(ref self): void {
        close_fd(self.fd);
    }
}

function main(): int32 {
    // `disposable` is the kind. FileHandle is the type. Disposable is the trait.
    // The kind requires the trait, and emits dispose() at scope end.
    disposable f: FileHandle = open_file("notes.txt");
    return 0;
}

Most languages bundle these together: an AutoCloseable is a type that does close-on-scope-exit, baked in. Splitting them lets the same FileHandle be passed around const, cleaned up via disposable, or pooled in a thread - without the type itself knowing about lifecycle.

Modules & imports

Every .yoop file is a module. Imports take a path string and a binding form. Paths are either relative (./, ../) or rooted at std/ for the standard library. 

import { parse, lex } from "./lexer.yoop";
import * as lex        from "./lexer.yoop";
import { parse as p }  from "./ast.yoop";
import "./init.yoop";                          // side-effect only

// Standard library uses the `std/` root.
import { Vec, vec_push } from "std/core/vec.yoop";
import { Request, Response, ok } from "std/http/types.yoop";

Symbols must be explicitly exported to be importable. Everything else is module-private. 

// math.yoop
export function add(a: int32, b: int32): int32 { return a + b; }
export type Point { x: int32, y: int32 }

function helper(): void { ... }     // not exported - private to this module

Re-exports use the same export keyword in front of a re-imported binding. The module graph is walked from the entry file, cycles are an error, and each module is type-checked once.

Types

Types appear on the right of a colon. The compiler does no implicit narrowing or widening between named numeric types - you reach for an explicit cast when you mean one.

Primitives

Integer types are two's-complement signed or unsigned, fixed width:

let a: int8;       let u: uint8;       // byte-sized
let b: int16;      let v: uint16;
let c: int32;      let w: uint32;      // int32 is also spelled `int`
let d: int64;      let x: uint64;
let n: usize;      let m: isize;       // pointer-width - used for sizes / indices

Floats follow IEEE-754:

let f: float32;     // also spelled `float`
let g: float64;

Other primitives:

let ok: bool      = true;
let nl: char      = '\n';            // evaluates to a uint32 codepoint
let s:  string    = "hello";          // immutable, UTF-8, zero-terminated for C interop
let b:  byte      = 0xFF;             // alias for uint8

Numeric literals are untyped until they reach a typed context - then they're range-checked and pinned. Out-of-range literals fail at compile time. Underscores can separate digits. 

let hp: int32   = 100;
let mask: uint8 = 0xFF;
let big: uint64 = 1_000_000_000;
let dt: float32 = 1.0 / 60.0;
let bits: uint8 = 0b1111_0000;
let mode: uint16 = 0o755;

let a: int32 = 10;
let b: int64 = a;                    // compile error - explicit cast required
let b: int64 = int64(a);             // ok

Casts use the type name as a call. Narrowing truncates; float ↔ int truncates toward zero.

Structs

Plain data. No inheritance. All fields are public. Field order in the declaration is the layout order. 

type Point {
    x: int32,
    y: int32,
}

type Rect {
    origin: Point,                   // nested struct field
    width:  int32,
    height: int32,
}

let p: Point = { x: 3, y: 4 };
let r: Rect  = { origin: { x: 0, y: 0 }, width: 10, height: 20 };
let dx: int32 = r.origin.x;          // field access chains

A bare struct literal { x: 1, y: 2 } has no standalone type - it must be pinned by an assignment target, a return type, or a call argument. The compiler uses that target to decide which struct it's building. 

let p: Point = { x: 1, y: 2 };           // pinned by `let p: Point`
return { origin: p, width: 4, height: 4 };  // pinned by the function's return type
draw({ x: 0, y: 0 });                    // pinned by the parameter type

Methods live in trait impl blocks, not in type bodies directly - see Traits.

Enums & unions

enum is a tagged sum type. Each variant is either bare or carries a record-style payload. Variants are referenced as EnumName.VariantName; the tag is an i32 in declaration order, so reordering variants is an ABI change. 

enum Shape {
    Circle  { radius: float32 },
    Square  { side: float32 },
    Empty,                            // no payload
}

let s: Shape = Shape.Circle { radius: 1.5 };
let e: Shape = Shape.Empty;

switch matches on the variant and binds payload fields by name. The compiler enforces exhaustiveness - every variant must be covered, or a default arm provided. 

switch (s) {
    case Shape.Circle { radius: r }: { printf(`circle r=${r}\n`); }
    case Shape.Square { side: a }:   { printf(`square a=${a}\n`); }
    case Shape.Empty:                { printf(`empty\n`); }
}

union is the untagged C-style sibling: a single byte buffer the size of its largest field, with overlapping access. Useful for FFI where you're modelling a real C union. The compiler does no discriminant tracking - you do. 

union IntFloatBits {
    i: int32,
    f: float32,
}

let bits: IntFloatBits = { i: 0x40490FDB };
printf(`pi-ish=${bits.f}\n`);

Arrays

Array types are written T[]. Arrays are fat pointers (data + length); xs.len reads the length. 

let xs: int32[] = [1, 2, 3];
let zs: Point[] = [{ x: 1, y: 2 }, { x: 3, y: 4 }];
let flags: bool[] = [true, false, true];

let first: int32 = xs[0];
let n: usize     = xs.len;

Slice syntax produces a zero-copy view over a range - the result is itself a T[], sharing storage with the source. 

let xs: int32[] = [10, 20, 30, 40, 50, 60];

let mid:  int32[] = xs[1..4];        // [20, 30, 40]
let tail: int32[] = xs[3..];         // [40, 50, 60]
let head: int32[] = xs[..3];         // [10, 20, 30]
let all:  int32[] = xs[..];          // view over the whole array

mid[0] = 99;                         // mutates xs[1] too - shared storage

Growable arrays live in the standard library as Vec<T> - see Standard library.

References

ref T is a non-null reference to a T. There is no pointer arithmetic and no null. Both the parameter declaration and the call site spell ref - aliasing is visible wherever it happens. 

function increment(ref counter: int32): void {
    counter = counter + 1;            // auto-deref on read and write
}

let n: int32 = 0;
increment(ref n);                     // call-site `ref` is required
printf(`n=${n}\n`);                   // n=1

References are how you mutate or pass-by-pointer without copying. Methods take ref self; trait-qualified calls take ref receiver as the first argument.

Functions

A plain function uses the function keyword, a parameter list with required type annotations, and a required return type (or void). 

function distance_sq(p: Point): int32 {
    return p.x * p.x + p.y * p.y;
}

function noop(): void { return; }

Kind-prefixed functions let you drop the function keyword. A kind like task (or a user-defined function-kind) sits where function would. 

task fetch(url: string): Bytes { ... }              // idiomatic
task function fetch(url: string): Bytes { ... }     // explicit; equivalent

task disposable open_remote(url: string): Handle { ... }   // multiple kinds

Parameters can be passed by reference with ref (see References). Function values in type position use the (p: T) => R arrow form - legal in field, parameter, return, and vtable slot annotations. 

type Handler {
    handle: (req: Request) => Response,
}

The => form is only a type annotation. There are no closure literals - function values come from named top-level functions or vtables (see Traits).

Control flow

Conditionals chain with else if / else:

if (x < 0) {
    printf(`negative\n`);
} else if (x == 0) {
    printf(`zero\n`);
} else {
    printf(`positive\n`);
}

while is the unconditional loop. for ... in walks an array element-by-element, binding a fresh copy each iteration. C-style for (init; cond; step) is available for index-driven loops. 

let i: int32 = 0;
while (i < 10) {
    i = i + 1;
}

let xs: int32[] = [10, 20, 30];
let sum: int32 = 0;
for x in xs {
    sum = sum + x;
}

for (j = 0; j < xs.len; j = j + 1) {
    printf(`xs[${j}]=${xs[j]}\n`);
}

break and continue jump out of / past the nearest enclosing loop. switch matches literals and enum variant patterns and is checked for exhaustiveness - see Enums. 

for v in xs {
    if (v == 20) { continue; }
    if (v == 40) { break; }
    sum = sum + v;
}

switch (code) {
    case 200: { printf(`ok\n`); }
    case 404: { printf(`not found\n`); }
    default:  { printf(`other: ${code}\n`); }
}

Traits

A trait describes a set of operations. self is always passed as ref - methods never take the receiver by value. 

trait Disposable {
    function dispose(ref self): void;
}

trait Iterable<T> {
    function next(ref self): { value: T, done: bool };
}

A type implements a trait by declaring implements after its name and providing the method bodies inside the type block. Multiple traits are grouped in parentheses. 

type FileHandle implements Disposable {
    fd: int32,
    function dispose(ref self): void {
        close_fd(self.fd);
    }
}

type Channel implements (Disposable, Iterable<Message>) {
    ...
}

Trait-qualified call syntax. Method calls are written Trait.method(ref receiver, ...), never receiver.method(...) or bare method(...). Two impls of the same method name on different traits never collide, because the call site says which trait it means. 

let f: FileHandle = open_file("notes.txt");
Disposable.dispose(ref f);            // explicit, qualified

Vtables give you runtime-polymorphic trait dispatch when you need a heterogeneous collection. A vtable declares a struct-shaped value with one slot per trait method: 

trait Op {
    function apply(ref self, x: int32): int32;
}

type Doubler implements Op {
    factor: int32,
    function apply(ref self, x: int32): int32 { return x * self.factor; }
}

type Adder implements Op {
    bias: int32,
    function apply(ref self, x: int32): int32 { return x + self.bias; }
}

vtable OpVT for Op {
    apply: (x: int32) => int32,
}

function dispatch(ref v: OpVT, x: int32): int32 {
    return Op.apply(ref v, x);        // indirect dispatch through the vtable
}

let d: Doubler = { factor: 5 };
let vt: OpVT   = OpVT.from(ref d);    // builder - captures the receiver
let n: int32   = dispatch(ref vt, 7); // 35

A Reader[] can mix any types whose impls were used to build the vtable values - each slot is the same nominal vtable type, even though the underlying struct differs.

Kinds

A kind attaches a usage contract to a binding - lifecycle, scoping, sharing, or layout rules. The kind prefix sits between let / const and the binding name; the keyword is optional when a kind prefix is present, defaulting to const. 

let disposable f: FileHandle = open_file("x.txt");
disposable f: FileHandle = open_file("x.txt");     // implicit const
let scoped result = fetch(url);
let pooled h      = fetch(url);

The built-in kinds:

  • disposable - requires the binding's type to implement Disposable, and emits Disposable.dispose(ref x) at scope end. Pairs with ? - cleanup also runs on early-return propagation.
  • scoped - for task handles. The compiler waits on the task at scope end and forbids the handle from escaping the declaring scope.
  • pooled - for task handles you want to keep around. Heap-allocated, refcounted, returnable. No auto-wait - you call wait h yourself.
  • joined - like scoped, but specifically forces the wait at the enclosing block's }.

User-defined kinds. A kind is a contract built from a closed set of clauses - requires Trait, ownsBlock, mustCall fn beforeScopeEnd, mustNotEscape scope, layout { align N; }, and so on. Each clause is one statement. 

kind disposable {
    requires Disposable;
    ownsBlock;
    mustCall dispose beforeScopeEnd;
}

kind simd_aligned {
    appliesTo type binding;
    layout { align 32; };
}

propagates<K> is the contract that says “this value carries another kind's obligation, and the obligation can't be silently dropped.” A binding of such a type has three legal exits:

  1. Declare the kind keyword on the binding (disposable arr: T = ...) and the compiler injects cleanup at scope end.
  2. Call the cleanup method directly (Disposable.dispose(ref arr)) before scope end.
  3. Return it from a function whose return type also declares propagates<K> - the obligation flows to the caller.

Drop the value on the floor with none of these and the compiler rejects the program. Composition uses & to combine kinds (disposable & scoped).

Clause reference

A kind body is a sequence of clauses drawn from a closed, compiler-owned set. There is no extension point; every clause is one of the forms below. Each clause is one ;-terminated statement of the form keyword args or keyword args { sub-clauses }.

  • appliesTo binding | parameter | field | function | type: which declaration sites accept this kind. Defaults to any value site.
  • requires Trait: the bound value's type must implement Trait. Repeat the clause for multiple traits; there is no list form.
  • provides Trait: the kind itself supplies the implementation of Trait for any value it's applied to (used by task to make calls return Task<T>).
  • ownsBlock: the bound name may take a trailing { ... } that narrows its scope. Without an explicit block the compiler synthesizes one at the tail of the enclosing scope; multiple block-owning bindings nest in reverse declaration order (LIFO cleanup).
  • mustCall fn beforeScopeEnd: fn must run before the binding's scope exits. The compiler emits the call on every exit path, including ? early returns and return.
  • mustNotEscape scope: the value cannot be returned from the declaring scope or stored where it would outlive that scope.
  • mustNotShare acrossScopes: the value cannot cross into a concurrent task.
  • autoJoin beforeScopeEnd: the compiler inserts a synthetic wait at scope exit. Used by joined for task handles.
  • restricts iteration { allow X; allow Y; forbid Z; }: which for ... in strategies are legal on this value (sequential, batched, simd, parallel). A contradiction-free intersection of allow/forbid clauses.
  • layout { align N; }: memory layout contract. Currently align is the only landed sub-clause; packing / SoA reservations are syntactic only.
  • propagates<K>: this value carries another kind's obligation, and that obligation must be discharged. See the section above for the three legal exits.
  • contains<K>: reserved syntax. A propagating value can be silently absorbed by a wrapper type that declares contains<K>. Not yet enforced; the workaround today is to discharge the obligation locally and not re-declare propagation on the return.
  • forbids io | globalState | ...: categories the function body may not touch. Reserved; syntax in place, enforcement landing alongside the effects work.

Reserved clause forms that are syntactically accepted but not yet enforced: mustCall fn beforeAny, mustCall fn afterAny, and mustCall { a; b; } beforeScopeEnd. The parser recognizes them and the typechecker emits a "not yet supported" note; the surface stays stable so user kinds written against them keep parsing.

Generics

Structs, functions, and traits can be parameterized over types with angle brackets. Type parameters appear after the declaration name and propagate into the body wherever the bare name is used. 

type Pair<A, B> {
    first: A,
    second: B,
}

function swap<A, B>(p: Pair<A, B>): Pair<B, A> {
    return { first: p.second, second: p.first };
}

let p: Pair<int32, string> = { first: 1, second: "one" };
let q: Pair<string, int32> = swap(p);

Call-site inference. Generic function calls infer type arguments from the argument types. There is no turbofish; if a parameter can't be inferred, the diagnostic tells you to constrain it elsewhere. 

function first<T>(xs: T[]): T {
    return xs[0];
}

let xs: int32[] = [10, 20, 30];
let n: int32    = first(xs);          // T inferred as int32 from xs

Trait bounds constrain a type parameter to types that implement a given trait. Inside the function body, calls of the trait's methods on the bound parameter compile to direct trait dispatch - each concrete instantiation gets its own monomorphic copy. 

function dispose_all<T implements Disposable>(ref items: T[]): void {
    for it in items {
        Disposable.dispose(ref it);
    }
}

Generic instantiation is lazy and cached: the compiler emits one monomorphic struct/function per concrete argument list, name-mangled by argument types. Codegen never sees an open type parameter.

Tasks & concurrency

Concurrency is a kind story - there are no async / await keywords. task is a kind applied to a function declaration; each call to that function is semantically a spawn that returns a Task<T>. 

task fetch(url: string): Bytes { ... }

function main(): int32 {
    let data     = fetch(url);        // synchronous-looking - wait inserted inline
    let joined d = fetch(url);        // concurrent - wait inserted at the next `}`
    let pooled h = fetch(url);        // returnable handle
    let result   = wait h;            // block on h, read the result

    _ = fetch(url);                   // fire-and-forget - result discarded
    return 0;
}

The binding's kind decides when the wait happens. Plain let x = f() with no kind inserts wait inline at that statement. joined defers until scope end. pooled never inserts a wait automatically - you call wait h yourself.

wait is suspendable. A waiting task drains the task queue on the calling thread until its target completes, so N-deep nested waits don't deadlock a fixed-size worker pool. The surface syntax is unchanged.

Bounded wait. wait_until(h, deadline_ns) returns a WaitResult<T> enum - Done, Timeout, or Cancelled. External cancellation lives behind cancel(h). 

import { WaitResult, now_ns } from "std/core/concurrency.yoop";

pooled h = fetch(url);
let deadline: uint64 = now_ns() + 250_000_000;   // 250ms
switch (wait_until(h, deadline)) {
    case WaitResult.Done { value: body }: { use(body); }
    case WaitResult.Timeout:              { abandon_request(); }
    case WaitResult.Cancelled:            { ... }
}

Fallible values & ?

A type is fallible if it's an enum with exactly two variants named Ok and Err, each carrying zero or one payload field. No marker trait - the shape itself is the contract. 

enum IntResult {
    Ok  { value: int32 },
    Err { error: int32 },
}

function parse_positive(n: int32): IntResult {
    if (n < 0) { return IntResult.Err { error: n }; }
    return IntResult.Ok { value: n };
}

The standard library defines Result<T, E> in std/core/types.yoop for the common case.

The postfix ? operator propagates an Err out of the enclosing function and binds the Ok payload locally: 

function add_two_positives(a: int32, b: int32): IntResult {
    let x: int32 = parse_positive(a)?;     // bail on Err, bind Ok.value to x
    let y: int32 = parse_positive(b)?;
    return IntResult.Ok { value: x + y };
}

? only compiles inside a function whose return type is also fallible. The default rule is same-shape - the Err payload types must match. For different Err payloads, the operand's type can declare implements Into<OuterErr> and the compiler inserts the conversion on the failure branch. 

type IoError implements Into<AppError> {
    code: int32,
    function into(ref self): AppError {
        return { msg: "io failed", code: self.code };
    }
}

function load(path: string): Result<Config, AppError> {
    const bytes = read_all(path)?;     // read_all: Result<_, IoError>
    // compiler calls IoError.into on the Err branch before building AppError
    ...
}

Live disposable bindings still get their cleanup inserted before the ? early return - you don't need try/finally machinery.

Intrinsics

Intrinsics are operations the compiler lowers directly, rather than calling out to a Yooperlang function body. They're declared in std/core/intrinsics.yoop inside an extern "intrinsic" from "compiler" block, so the user-facing surface is exactly the import: 

import * as intr from "std/core/intrinsics.yoop";

let buf: int32[] = intr.heap_alloc(8);     // 8-slot heap-allocated int32[]
intr.heap_free(buf);                       // matching free

Std value imports must use the namespace form (import * as intr) so short names like heap_alloc can't shadow user identifiers. The full intrinsic surface: 

// std/core/intrinsics.yoop
extern "intrinsic" from "compiler" {
    function heap_alloc<T>(n: usize): T[];
    function heap_free<T>(a: T[]): void;
    function string_as_bytes(s: string): uint8[];
    function string_from_bytes_unchecked(buf: uint8[]): string;
    function array_slice<T>(xs: T[], start: usize, end: usize): T[];
}

What each one does:

  • heap_alloc<T>(n): allocate a fresh T[] of length n on the heap. Storage is zero-initialized. The returned fat pointer is owned by the caller until heap_free.
  • heap_free<T>(a): free a fat pointer previously returned by heap_alloc. Calling with anything else (a stack slice, a slice view) is undefined behavior.
  • string_as_bytes(s): zero-copy view over the UTF-8 storage of a string as uint8[]. The view shares storage with the source string; mutating it is undefined behavior since strings are immutable.
  • string_from_bytes_unchecked(buf): reinterpret a uint8[] as a string without validating UTF-8. Use the checked string_from_bytes in std/core/strings.yoop for untrusted input; this form exists for FFI hot paths where the producer already guarantees validity.
  • array_slice<T>(xs, start, end): explicit slice form. Equivalent to xs[start..end] in user code; provided as a callable for generic code that builds slice ranges dynamically.

Two more intrinsics come in through std/core/concurrency.yoop; they're the bounded-wait and external-cancel forms for Task<T>: 

// std/core/concurrency.yoop
extern "intrinsic" from "compiler" {
    function wait_until<T>(h: Task<T>, deadline_ns: uint64): WaitResult<T>;
    function cancel<T>(h: Task<T>): void;
}

printf is the one exception to the namespace rule: it's globally callable without an import, since the name is distinctive enough that shadowing isn't a real risk. Everything else routes through import * as ....

Standard library

The standard library lives under the std/ import root, the only path prefix the resolver accepts besides relative paths. Each module below is grouped by directory; signatures are transcribed from the actual .yoop sources, so this is the inventory, not a wish list. Generic types and functions keep their <T> parameters in the listing.

Value imports from std/ must use the namespace form (import * as ns from "std/..."); type, trait, kind, and enum imports may keep the named form. Both are shown in the examples.

std/core

The foundation that every other module imports from. Result and Option types, the staple traits, the disposable kind, strings, bytes, vectors, formatting, intrinsics, and the concurrency primitives.

std/core/types.yoop

The two canonical algebraic types. Result is the fallible shape ? recognizes; Option is the value-or-absent shape that lookups return. 

export enum Result<T, E> {
    Ok  { value: T },
    Err { error: E },
}

export enum Option<T> {
    Some { value: T },
    None,
}

std/core/traits.yoop

The shared trait surface. Readable and Writable are the byte-stream traits; Display is the human-string conversion; Iterable is the trait for ... in desugars onto; Into is the cross-shape error conversion the ? operator looks up. 

export trait Readable {
    function read(ref self, ref buf: uint8[]): Result<c_ssize_t, string>;
}

export trait Writable {
    function write(ref self, ref buf: uint8[]): Result<c_ssize_t, string>;
    function flush(ref self): FlushOutcome;
}

export enum FlushOutcome {
    Ok,
    Err { error: string },
}

export trait Display {
    function to_string(ref self): string;
}

export enum IterStep<T> {
    Yield { value: T },
    Done,
}

export trait Iterable<T> {
    function next(ref self): IterStep<T>;
}

export trait Into<T> {
    function into(ref self): T;
}

std/core/kinds.yoop

The Disposable trait and the disposable kind live together, since the kind is what makes the trait automatic at scope end. 

export trait Disposable {
    function dispose(ref self): void;
}

export kind disposable {
    appliesTo binding;
    requires Disposable;
    mustCall dispose beforeScopeEnd;
}

std/core/vec.yoop

Growable typed vector. Vec<T> owns a backing buffer and implements Disposable; the propagates<disposable> on every returning function means the caller has to decide how to discharge cleanup. 

export type Vec<T> implements Disposable propagates<disposable>;

export function vec_new<T>(initial_cap: usize): Vec<T> propagates<disposable>;
export function vec_push<T>(v: ref Vec<T>, value: T): void;
export function vec_get<T>(v: ref Vec<T>, i: usize): T;
export function vec_set<T>(v: ref Vec<T>, i: usize, value: T): void;
export function vec_clear<T>(v: ref Vec<T>): void;
export function vec_as_array<T>(v: ref Vec<T>): T[];

std/core/strings.yoop

String comparison, search, slicing, concatenation, and the checked UTF-8 conversion from uint8[]. 

export function string_from_bytes(buf: uint8[]): Result<string, string>;
export function string_eq(a: string, b: string): bool;
export function string_eq_ignore_ascii_case(a: string, b: string): bool;
export function string_starts_with(s: string, prefix: string): bool;
export function string_index_of(s: string, needle: string): usize;
export function string_slice(s: string, start: usize, end: usize): Result<string, string>;
export function string_hash(s: string): uint64;
export function string_concat(a: string, b: string): string;
export function string_concat_all(parts: string[]): string;

std/core/bytes.yoop

Byte-buffer counterparts for the string ops, plus an integer parser that reports how many bytes it consumed. 

export type BytesParsed { value: int64, consumed: usize }

export function bytes_eq_ignore_ascii_case(a: uint8[], b: uint8[]): bool;
export function bytes_index_of(buf: uint8[], needle: uint8): usize;
export function bytes_index_of_seq(buf: uint8[], needle: uint8[]): usize;
export function bytes_starts_with(buf: uint8[], prefix: uint8[]): bool;

std/core/format.yoop

std/collections

Generic data structures. All three are Disposable and propagate their cleanup obligation to the caller via propagates<disposable>. Maps and sets use a KeyOps<K> witness for hashing and equality; the most common key types ship with pre-built ops.

std/collections/map.yoop

export type KeyOps<K> {
    hash: (k: K) => uint64,
    eq:   (a: K, b: K) => bool,
}

export type Map<K, V> implements Disposable propagates<disposable>;
export type MapEntry<K, V> { key: K, value: V }
export type MapIter<K, V> implements Iterable<MapEntry<K, V>>;

export function map_new<K, V>(initial_cap: usize, ops: KeyOps<K>): Map<K, V> propagates<disposable>;
export function map_insert<K, V>(ref m: Map<K, V>, key: K, value: V): bool;
export function map_get<K, V>(ref m: Map<K, V>, key: K): Option<V>;
export function map_contains_key<K, V>(ref m: Map<K, V>, key: K): bool;
export function map_remove<K, V>(ref m: Map<K, V>, key: K): bool;
export function map_len<K, V>(ref m: Map<K, V>): usize;
export function map_clear<K, V>(ref m: Map<K, V>): void;
export function map_iter<K, V>(ref m: Map<K, V>): MapIter<K, V>;

std/net

TCP sockets through the host OS. The disposable handles (TcpListener, TcpStream) hold the underlying file descriptor; the Result-shaped return types (ListenResult, AcceptResult, ConnectResult) carry either a connected handle or an error string. TcpStream implements Readable and Writable, so it slots straight into the byte-stream traits.

std/net/tcp.yoop

export type TcpListener implements Disposable propagates<disposable>;
export type TcpStream   implements (Disposable, Readable, Writable) propagates<disposable>;

export type ListenResult  implements Disposable propagates<disposable>;
export type AcceptResult  implements Disposable propagates<disposable>;
export type ConnectResult implements Disposable propagates<disposable>;

export function tcp_listen(host: string, port: int32, backlog: int32): ListenResult propagates<disposable>;
export function tcp_accept(ref l: TcpListener): AcceptResult propagates<disposable>;
export function tcp_connect(host: string, port: int32): ConnectResult propagates<disposable>;

std/http

A minimal HTTP/1.1 surface. Request and response types, a status code helper layer, header storage, and a server loop that takes any type implementing Handler. Parser and server are written in Yooperlang on top of std/net.

std/http/types.yoop

export enum HttpMethod  { Get, Head, Post, Put, Delete, Options, Patch, Other }
export enum StatusClass { Informational, Success, Redirection, ClientError, ServerError, Unknown }
export type StatusCode  { code: int32 }

export function status(code: int32): StatusCode;
export function status_class_for(code: int32): StatusClass;
export function reason_phrase(code: int32): string;

export function ok(): StatusCode;                  // 200
export function bad_request(): StatusCode;         // 400
export function not_found(): StatusCode;           // 404
export function method_not_allowed(): StatusCode;  // 405
export function server_err(): StatusCode;          // 500

export type HeaderEntry { name: string, value: string }
export type Headers  implements Disposable propagates<disposable>;
export type Request  implements Disposable propagates<disposable>;
export type Response implements Disposable propagates<disposable>;

export function headers_new(cap: usize): Headers propagates<disposable>;
export function headers_add(ref h: Headers, name: string, value: string): void;
export function headers_get(ref h: Headers, name: string): string;
export function headers_has(ref h: Headers, name: string): bool;

export function response_new(): Response propagates<disposable>;

std/http/server.yoop

export enum HandleOutcome { Ok, Err }

export trait Handler {
    function handle(ref self, ref req: Request, ref resp: Response): HandleOutcome;
}

export type ServeOutcome { served: int32, error: string }

export function serve_n<H implements Handler>(
    ref l: TcpListener,
    ref handler: H,
    n: int32,
): ServeOutcome;

serve_n runs the handler up to n times (or forever when n == 0). Because H is a generic type parameter constrained to Handler, each call site monomorphizes into a direct call - no vtable indirection in the hot path.

std/log and std/debug

Two small top-level modules. Logging routes to stderr with a level prefix; debug panics print and abort. 

// std/log.yoop
export function info(msg: string): void;
export function warn(msg: string): void;
export function error(msg: string): void;

// std/debug.yoop
export function panic(msg: string): void;
export function unreachable(msg: string): void;
export function assert(cond: bool, msg: string): void;

Call shape (namespace form required): 

import * as log from "std/log.yoop";
import * as dbg from "std/debug.yoop";

log.info("listening on 18080");
dbg.assert(buf.len > 0, "buffer must be non-empty");
